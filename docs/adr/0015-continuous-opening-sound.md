# ADR-0015：開啟中連續播放（取代 `LidOverbent` 的單次觸發）

- 狀態：Accepted（修訂 ADR-0005 的 `LidOverbent`）
- 日期：2026-10-25

## Context

ADR-0005 的 `LidOverbent` 只在角度往上穿越 120° 時播一次。實際使用時想要的是「打開螢幕的過程中」就有聲音：
在 30°～120° 之間往上打開時播放，手停下來聲音就停，繼續打開就從剛才停的地方接著播。

## Decision

- `LidOverbent` 改為**連續事件**（沿用同一個 `EventKind`、同一組音效，profile 與 `.spankpack` 格式不變）。
  UI 名稱改為「開啟中／Opening」。
- 播放區間：`opening_start_deg`（新設定，預設 30°）～`overbend_threshold_deg`（沿用，預設 120°）。超過 120° 不播。
- 「正在打開」的判定（`LidDetector::opening`）：
  - 從靜止位置往上累積 ≥ 2° 才算開始（感測器解析度 1°，單步 1° 可能是抖動）。
  - 300 ms 內沒有再往上，或比這次最高點往下 ≥ 2°，就算停止。
    角度值實測約每 110 ms 才更新一次（即使以 30 Hz 輪詢），所以 300 ms 涵蓋慢速打開。
- 播放（`Orchestrator`）：
  - 開始打開 → 播放（優先權不變，仍為 5）；只在第一次播放時送出 `Fired`，之後的續播不算新事件。
  - 停止或往下 → `Output::StopSound(priority)`，50 ms 淡出，記住已播放的長度。
  - 再往上 → 從記住的位置續播（`PlayRequest::offset_ms`，10 ms 淡入）。
  - **每次打開只播一遍**：播完就不再播；角度降到 30° 以下才算新的一次打開（重新挑音效、從頭播）。
  - 暫停、靜音、睡眠、鎖定、換 profile 音效時立即停止。
- 混音器：`Mixer::stop_priority` 只淡出指定優先權的聲音；被停止、正在淡出的聲音不再擋住新的請求。

## Consequences

- 從睡眠中打開螢幕時，喚醒的 `LidOpened` 播放中若繼續往上打開，會被優先權較高的開啟音效打斷。
- 播放位置以感測器時間估算，與實際音訊有數十毫秒誤差（音訊串流從暫停恢復約 20–40 ms），聽感上可接受。
- 設定頁目前只能調整上限（`overbend_threshold_deg`），30° 起點只能改設定檔。
