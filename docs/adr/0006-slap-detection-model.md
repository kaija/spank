# ADR-0006：拍打偵測 — 力道分級、連擊、誤觸抑制

- 狀態：Accepted（參數由 Spike S2 與 T10 / T23 trace 決定，見 [spike-report](../spike-report.md)；偵測改在 App 內執行，見 ADR-0014）
- 日期：2026-10-24

## Context

加速度計同時會收到：拍打、打字、觸控板按壓、放下筆電、螢幕開合、喇叭自身振動。
需要在不額外要求權限的前提下，把拍打分出來並分級。

## Decision

### 管線

1. **Sensor thread（App 內，ADR-0014）**：各軸高通濾波去重力 → 計算 |a| → 超過 `max(觸發門檻 0.2 g, k × 自適應 noise floor)` 時，擷取 80 ms 視窗特徵
   （`peak_g`、`energy`、`duration_ms`、`hf_ratio` 高頻能量比、`ts`）→ 送出 `ImpactCandidate`。
2. **App**：
   - **抑制閘（Suppression gates）**：以下期間丟棄候選
     - 螢幕角度正在變化中 + 結束後 500 ms
     - App 自己正在播放音效 + 結束後 200 ms
     - 打字：預設用訊號特徵（打字 = 小振幅、密集、`hf_ratio` 高；拍打 = 單一大峰值 + 低頻推動）；
       進階設定可開「精準模式」（需 Input Monitoring 權限，鍵盤/觸控板輸入後 300 ms 內丟棄）。
   - **分級**：依校準後的三個門檻分為 `Light` / `Medium` / `Hard`。
   - **連擊**：5 秒內第 3 次（含）以上 → `Combo(n)`，取代該次分級事件。
   - **Refractory**：開窗後 150 ms 內不再開窗。T10 的快速連拍間隔只有 ~200 ms，300 ms 會漏掉 3／6 下；
     重拍 ~100–150 ms 後的回彈改由「rebound 檢查」排除（見下）。

### 參數（T23 以 `fixtures/traces/m4air-v1` 調校，M4 Air）

| 參數 | 值 | 依據 |
|------|----|------|
| 高通截止 | 2 Hz | 去重力與緩慢傾斜 |
| 觸發門檻 `trigger_g` | 0.15 g | 最輕的拍打只有 0.16 g；打字由下一列擋掉 |
| 噪音門檻 | 峰值 > 12 × noise floor（1 s EMA，接受衝擊後凍結 250 ms） | 拍打 ≥ 21 ×、打字 ≤ 8 × |
| 頻率門檻 | 視窗平均頻率 ≥ 16 Hz | 拍打／拍桌 20–35 Hz；拿起、走路、開合 ≤ 12 Hz |
| Rebound | 接受後 250 ms 內，峰值須 ≥ 0.45 × 前一下 | 重拍回彈 ~30 %；連拍第二下 ≥ 56 % |
| Refractory | 150 ms | 快速連拍間隔 ~200 ms |
| 分級門檻 | 預設 0.15 / 0.3 / 0.5 g，校準決定 | 實測輕 0.16–0.38、中 0.2–0.34、重 0.55–0.68 g，輕／中重疊 |

結果：23 個人工標註拍打（含 3 次拍桌）precision 1.00、recall 1.00；參數在 k 12–16、頻率 14–20 Hz、
refractory 150–200 ms 範圍內都維持 1.00。只有一台機器、一位使用者，需要更多 trace 驗證。

### 校準

首次啟用拍打時 30 秒校準：輕 / 中 / 重各拍一次，再打字數秒學習 noise floor。結果存 `calibration.json`，可重做。

## Consequences

- 需要真實 trace 才能調參；Spike S2 必須錄製拍打、打字、開合、放桌上、走路攜帶等場景。
- 外接螢幕暫停規則 **不** 預設啟用（使用者未選）。
- ~~單純峰值門檻已能過濾打字~~ → **T10 trace 推翻此結論**：大力打字達 0.198 g、拿起／放下／走路達 0.25–0.35 g、拍桌子達 1.9 g。
  T23 改用自適應噪音門檻（擋打字）＋平均頻率（擋拿起、走路）＋ rebound 檢查；峰值門檻只用來開窗。
- 喇叭播放的振動可忽略（0.012 g），播放抑制閘僅作保險。
- **拍桌子視同拍打**（2026-10-24 決策，先求簡單）：不區分拍電腦與拍桌子；拍桌子峰值大（1.3–1.9 g），通常會判成 `Hard`。
  代價是別人碰到桌子也可能觸發；若使用者回報太吵，再考慮排除或另立 `TableBump` 事件（Phase 2）。
  T23 仍需用波形特徵排除打字、拿起／放下、走路等**非撞擊**動作。

## Alternatives

- **單一觸發**：太單調。
- **強制 Input Monitoring**：權限提示嚇人。
- **root helper 內判斷**：ADR-0014 已移除 helper。
